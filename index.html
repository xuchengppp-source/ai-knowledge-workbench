生产级 AI Agent 知识体系总览：层级·特性·术语

⏱ 8 分钟2.4k 字更新 07-06来源 Obsidian
生产级 AI Agent 不是更聪明的聊天机器人，而是把模型判断、工具执行、数据知识、记忆管理、流程编排、安全治理和持续运营组合成一套可长期托付的 AI 工程系统。

一、概念地图：所有框架回答同一个问题

这套知识体系只回答一个核心问题：

AI Agent 怎么从"能用"变成"可托付"？
核心问题：AI Agent 怎么从"能用"变成"可托付"？
├─ 能力阶梯 —— 它怎么演进？
│  聊天AI → Agent → Agent with Harness
│  （能说 → 能做 → 能托付）
├─ 业务分界 —— 它做什么？
│  数据呈现（经营参谋）vs 管理闭环（经营系统）
├─ 工程实现 —— 怎么建？
│  六层架构 = 系统职责怎么分
│  十层工程链 = 按业务需要检查
│  三维工程能力 = 团队怎么分工
├─ 成熟度 —— 做到什么程度？
│  不是独立框架，是能力阶梯在客户身上的落点
└─ 术语表 —— 所有概念的索引

二、核心判断：看工程环节，不看名词

判断生产级 Agent 时，不要问"它有没有用我们的术语"，而要问：

  • 业务对象是否清楚？
  • 业务流程是否清楚？
  • 状态流转是否清楚？
  • 工具调用和权限边界是否清楚？
  • 高风险动作是否有人审？
💡 美团餐饮 AI 就是一个现实对标：未必用"十层工程链"叫法，但业务对象、数据入口、工具落点、场景约束已经设计得很强。
