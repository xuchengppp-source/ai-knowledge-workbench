# AI 知识学习工作台 · PRD

## 1. 产品定位

徐总知识库「放大循环」的呈现面：知识底座不断被外部养料喂养，方向从养料中诞生，专题从底座提炼而成，再沉淀回底座。工作台让这个循环**可见、可操作、可实时跟进**——电脑端直观呈现，手机端零碎时间交互。

## 2. 产品概念：知识放大循环

### 2.1 三个层面

```text
真相层（Obsidian）   知识唯一来源：正式专题 / 原始资料 / 每日增量 / 每周复盘
                     编译只读，不反向写回

循环层（问答与沉淀） 方向（问题）→ 专题（理解）→ 回流底座 → 新方向

状态层（Supabase）   方向活跃度 / 成熟度 / 养料状态 / 你的操作痕迹 —— 实时
```

### 2.2 底座 → 方向 → 专题

```text
             外部养料：抖音视频 / ChatGPT 深聊 / 微信问答（克里斯）
                          ↓ 不断喂入
            ┌─ 知识底座（Obsidian · 广阔底层）─────────────┐
            │  每日增量 → 每周复盘 → 正式专题 → 问题专题    │
            └────────────────────────────────────────────┘
                            ↑ 提炼                ↓ 沉淀回流
                   方向（一个问题）────→ 专题（对这个问题的理解）
                   先有养料，后有方向    从底座提炼知识形成理解
```

- **知识底座**：广阔底层知识源，被外部养料持续喂养、持续生长。
- **学习方向（简称方向）**：一个问题。先有养料（刷到视频、聊天、脑中想法），后有方向；代表徐总当前关注。
- **专题**：对问题的理解。从底座提炼知识、结构化沉淀；专题知识又回流底座。

一句话：**方向从底座取料，专题向底座还料**，知识在「问 → 提炼 → 沉淀 → 再问」中放大。

## 3. 目标用户与使用场景

- 核心用户：徐总本人（个人私有，不做分享）。
- 一天（手机）：看今天知识库变化与方向生长 → 顺专题学「问题 → 回答 → 关联 → 追问」→ 随手标记/归类 → 想深了去微信问克里斯。
- 一周（电脑）：看这周沉淀了什么、哪些值得深挖（不是增长数字）→ 标记复盘进展 → 成熟内容回流正式专题。

### 5.3 页面职责

| 页面 | 内容 |
|---|---|
| 方向墙（首页） | 方向卡片：为什么关注 / 活跃度 / 最近更新 / 材料数；快速新增；今天有更新标记；待归类提示 |
| 方向详情 | 为什么关注 · 想搞清楚的问题 · 关联专题 / 笔记 / 资料 · 状态与时间线 |
| 专题理解 | 问题 → 回答结构（原文 / 提炼 / 可复用框架）→ 关联 → 下一步追问 |
| 知识基座 | 三大主线 · 节点 · 每日增量 · 每周复盘 · 全局搜索 |

### 5.4 状态可视化（2026-08-05：减少文字，用视觉表达状态）

状态不靠文字描述，用可读视觉元素表达：

| 状态 | 可视化表达 |
|---|---|
| 活跃度 | 3 档热力点（高亮 / 中亮 / 灰），呼吸动画表示「正在热」 |
| 最近更新 | 「今天 · 新增 1 条专题」「26 天前 · 没有新东西」，静置方向橙色警示 |
| 材料数 | 图标计数：专题 📘 / 笔记 📝 / 资料 📎 |
| 今天有更新 | 方向卡片高亮描边 + 「今天有更新」标记 |
| 待归类 | 底部胶囊徽章：「3 条待归类 ›」 |

原则：方向墙只回答「这个方向最近还活着吗」，不设完成态。专题会持续增长，不存在「已沉淀」终态；防囤积靠静置现形，不靠阶段标签。

## 6. 互动环节（状态层的用户入口）

- 方向墙：➕ 新建方向（随手抛一个想法，后面再丰富）。
- 方向详情：追加「想搞清楚的问题」、归入养料、标记理解。
- 专题理解：「下一步追问」（引导去微信问克里斯）、「已追问」标记。
- 方向墙「待归类」提示：点击展开视频文案列表，每条「归入方向 / 已整理」。

所有操作实时写入 Supabase，双端同步。工作台从「看知识」变成「操作知识」。

## 7. 养料管线与角色分工

### 7.1 完整链路

```text
外部养料（抖音视频 / 聊天 / 想法）
  → 飞书艾特伊森（WorkBuddy 机器人）→ Skills 转运豆包 → 提取全部文案
  → 形成知识库「未整理」原稿
  → WorkBuddy 基础录入 + 轻加工（归档、规范化、标签）→ 原始资料 / 未整理层
  → Codex 深度梳理 → 正式专题 / 笔记成型
  → 编译上架（3 小时指纹轮询）
```

内容分流（2026-08-04 确认）：

- **ChatGPT 深聊**：直接进入专题笔记（知识库正式层），**不走待整理**；
- **视频分享提取文案**：目前唯一经过「待整理」的内容，量不稳定；
- 因此待整理不设独立入口，仅作为方向墙轻量提示（量少时自然消失，不长期空置）。

```text

方向形成（质量闸门在徐总）：
  想到问题 → 微信问克里斯 → 克里斯从 Obsidian 检索筛选回答
    → 徐总判断：① 回答行不行？ ② 愿不愿继续学？
    → 都成立 → 沉淀为问题专题 → 可继续延伸、总结
```

### 7.2 角色分工

| 角色 | 职责 | 边界 |
|---|---|---|
| 伊森（WorkBuddy） | 转运豆包提取文案；基础录入 + 轻加工；飞书随时可达，实时归位 | 不做专题成型 |
| 克里斯（OpenClaw / MiniMax M3） | 基于 Obsidian 的回答筛选 | 不做文案提取，不负责最终梳理质量 |
| Codex（DeepSeek） | 深度梳理：跨方向关联、要点提炼、专题成型 | 依赖电脑，人在外面时不可即时 |
| 徐总 | 质量闸门；方向判断；触发「梳理一下 XX」 | — |

实时性设计：人在外面时伊森实时归位（基础整理），深度提炼等回电脑由 Codex 补做，或口头触发。

## 8. 状态层（Supabase，字段草案）

- 方向：id · title · why（为什么关注）· questions（想搞清楚的问题）· heat（1-3 活跃度）· last_at（最近更新文案）· last_note（动态）· today（今天是否有更新）· materials（关联数）· created_at · last_active_at；
- 专题：id · topic_id · question · answer_summary · related_nodes · next_questions · status · updated_at；
- 养料：id · source_type（douyin / chatgpt / wechat）· source_url · content_raw · status（待整理 / 已整理 / 已入库）· topic_id · created_at；
- 互动日志：id · kind（新增方向 / 归类 / 追问）· target · created_at（供生长时间线使用）。

### 8.1 智能体协作任务层（Taskboard，与 Supabase 并行）

智能体任务接力不并入 Supabase，复用 `dashi-taskboard` 作为任务事实层（详见 `04-智能体协作状态层.md`）。

- 任务卡：title · assignee（agent:codex / agent:chris / agent:ethan / agent:lucas / human:xucheng）· status（todo → in_progress → in_review → done / blocked / canceled）· 评论（产出物 Obsidian 链接 + 验证结果 + 返工要求）。
- 并发：乐观锁（version + `--if-version`），多个智能体同时操作时防抢单。
- 接入：各智能体一个极简 skill 包 `taskctl`；Codex 用现有 `manage-taskboard` skill。
- 展示：工作台「协作」入口；手机端先走静态快照 + 局域网，稳定后评估云模式。
- 分工：审核默认 Codex；伊森做录入 / 整理 / 预审；克里斯只做微信端搬运与建卡，不碰深度梳理。

## 9. 非功能需求

- 知识正文静态托管（GitHub Pages），状态层 Supabase Realtime；接入信息存本地 `.env`，不进 Git。
- 移动端自适应：宽度跳转 + `?desktop=1` 强制桌面。
- 自动化：现有 3 小时指纹轮询不动，编译产物 upsert Supabase。
- 隐私：白名单过滤，个人敏感内容不进仓库、不上前端。

## 10. 验收标准（草案）

- 电脑端、手机端均能浏览最新知识；方向墙 / 方向详情 / 养料队列可用。
- 方向从「抛想法 → 克里斯回答 → 质量闸门 → 沉淀专题」全链路可走通。
- 互动操作实时写入 Supabase 并在双端同步可见。
- Obsidian 有更新时，工作台在窗口期内自动上线。

## 13. 产品过程总结回流

`docs/` 是 L2 过程材料层。产品到里程碑（如原型定稿 / 路线二跑通）时，按知识流水线把「需求探测 → 架构决策 → 落地过程」提炼成 Obsidian 正式专题，沉淀后继续作为未来提问的知识底座。
